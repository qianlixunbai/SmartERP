## 2. クイックスタート（開発環境）

### 2.1 データベース初期化

```bash
# 1. MySQL サービスを起動
# 2. データベースを作成
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS smartoa DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 3. マイグレーションスクリプトを順に実行
mysql -u root -p smartoa < docs/mysql-p0-upgrade.sql
mysql -u root -p smartoa < docs/mysql-p1-upgrade.sql
mysql -u root -p smartoa < docs/mysql-p3-bcrypt.sql
mysql -u root -p smartoa < docs/mysql-p4-parallel.sql
mysql -u root -p smartoa < docs/mysql-p5-timeout.sql
```

マイグレーションスクリプト説明：

| スクリプト | 内容 |
|---|---|
| `mysql-p0-upgrade.sql` | テーブル作成 + 4 基本テーブル + シードデータ |
| `mysql-p1-upgrade.sql` | approval_node + template_field + 新フィールド |
| `mysql-p3-bcrypt.sql` | パスワード BCrypt 暗号化移行 |
| `mysql-p4-parallel.sql` | 並列承認（sign_type + approver_ids + approval_task テーブル） |
| `mysql-p5-timeout.sql` | タイムアウトエスカレーション（timeout 関連フィールド） |

### 2.2 バックエンド起動

```bash
# プロジェクトルートディレクトリに移動
cd smartoa

# 方式一：Maven Wrapper（推奨、Maven のインストール不要）
cd backend && ./mvnw spring-boot:run

# 方式二：Maven
cd backend && mvn spring-boot:run

# 方式三：先にビルドしてから実行
cd backend && ./mvnw clean package -DskipTests
java -jar backend/target/smartoa-0.0.1-SNAPSHOT.jar
```

**確認：** `http://localhost:8080/api/user/current` にアクセスし、401 が返れば起動正常。

### 2.3 フロントエンド起動

```bash
# フロントエンドディレクトリに移動
cd smartoa/frontend

# 依存関係をインストール（初回）
pnpm install

# 開発サーバーを起動
pnpm run dev
```

**確認：** `http://localhost:5173` にアクセスし、ログインページが表示されれば正常。

## 3. 設定説明

### 3.1 バックエンド設定（application.properties）

```properties
# データベース接続
spring.datasource.url=jdbc:mysql://localhost:3306/smartoa?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf-8
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
spring.datasource.username=root
spring.datasource.password=123456

# MyBatis-Plus
mybatis-plus.configuration.log-impl=org.apache.ibatis.logging.stdout.StdOutImpl
mybatis-plus.configuration.map-underscore-to-camel-case=true

# JWT
jwt.secret=<your-secret-key-at-least-256-bits>
jwt.expiration=86400000

# 定期タスク（タイムアウトチェック間隔、ミリ秒）
# spring.task.scheduling.pool.size=5
```

### 3.2 フロントエンド設定

Vite プロキシ設定は `vite.config.js` にあらかじめ設定済みで、開発モードでは `/api` リクエストが自動的に `http://localhost:8080` にプロキシされます。

## 4. 本番デプロイ

### 4.1 フロントエンドビルド

```bash
cd frontend
pnpm run build
# 出力先: frontend/dist/
```

### 4.2 バックエンドビルド

```bash
cd backend && ./mvnw clean package -DskipTests
# 出力先: target/smartoa-0.0.1-SNAPSHOT.jar
```

### 4.3 デプロイ方式

**方式一：フロントエンド・バックエンド分離（Nginx リバースプロキシ）**

```
nginx.conf:
server {
    listen 80;
    server_name oa.example.com;

    # フロントエンド静的リソース
    location / {
        root /var/www/smartoa/dist;
        try_files $uri $uri/ /index.html;
    }

    # バックエンド API プロキシ
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

**方式二：JAR に静的リソースを内包**

`frontend/dist/` の内容を `src/main/resources/static/` にコピーし、再パッケージします。Spring Boot が自動的にフロントエンドファイルをホスティングします。

## 6. よくある質問

### Q1: バックエンド起動時に "Access denied for user" エラーが発生

**解決策：** `application.properties` の MySQL ユーザー名とパスワードが正しいか確認してください。デフォルトは root/123456 です。

### Q2: フロントエンドのページが空白

**解決策：**
1. バックエンドが起動済みで 8080 ポートで動作していることを確認
2. ブラウザの F12 → Console で CORS エラーが発生していないか確認
3. Vite プロキシが正常に動作しているか確認

### Q3: ログイン後に「ユーザーが存在しません」と表示される

**解決策：** データベースマイグレーションスクリプトが実行済みで、シードデータが挿入されていることを確認してください。

### Q4: 申請提出時に「直属上司が未割り当てです」と表示される

**解決策：** `sys_user` テーブルで当該ユーザーの `direct_leader_id` が設定されていることを確認してください。現在のシードデータでは zongjian1/zongjian2 に直属上司は設定されていません。

### Q5: 承認後に状態が変わらない

**解決策：** 正しい承認者アカウントでログインしていることを確認してください。申請提出後、`current_approver_id` は直属上司の ID（SINGLE モード）になります。または `approval_task` テーブル（並列モード）を確認してください。

### Q6: ECharts グラフが表示されない

**解決策：** `pnpm install` が実行済みで、echarts 依存関係がインストールされていることを確認してください。

### Q7: タイムアウト自動処理がトリガーされない

**解決策：**
1. 起動クラスに `@EnableScheduling` が設定されていることを確認
2. ノードに `timeoutHours` と `timeoutAction` が正しく設定されているか確認
3. タイムアウトチェックは 5 分ごとに実行されるため、対応する時間の経過を待つ必要があります

### Q8: 並列承認タスクが表示されない

**解決策：** `mysql-p4-parallel.sql` が実行済みで、`approval_task` テーブルが作成されていることを確認してください。
