## 1. はじめに
> <span style="color: #888888;">## 1. 引言</span>

### 1.1 作成目的
> <span style="color: #888888;">### 1.1 编写目的</span>

本文書は、SmartOA承認フロー管理システムの機能要件と非機能要件を詳細に記述し、開発、テスト、検収の基盤として提供することを目的とする。
> <span style="color: #888888;">本文档旨在详细描述 SmartOA 审批流管理系统的功能需求和非功能需求，作为开发、测试和验收的依据。</span>

### 1.2 プロジェクト背景
> <span style="color: #888888;">### 1.2 项目背景</span>

企業内の日常的な承認（休暇申請、経費精算、残業申請など）は、従来、紙の伝票や断片化したインスタントメッセージツールに依存しており、非効率、紛失しやすい、追跡が困難などの問題があった。SmartOAは、軽量なオンライン承認ソリューションを提供する。
> <span style="color: #888888;">企业内部日常审批（请假、报销、加班等）传统上依赖纸质单据或碎片化的即时通讯工具，存在效率低、易丢失、难追溯等问题。SmartOA 提供一套轻量级的线上审批解决方案。</span>

### 1.3 適用範囲
> <span style="color: #888888;">### 1.3 适用范围</span>

- 開発チーム：要件の詳細を理解し、コーディング実装を導く
- テストチーム：テストケース作成の根拠
- ユーザー／レビュー担当者：機能の完全性を検収
> <span style="color: #888888;">
> - 开发团队：理解需求细节，指导编码实现
> - 测试团队：编写测试用例的依据
> - 用户/评审方：验收功能是否完整
> </span>

### 1.4 用語定義
> <span style="color: #888888;">### 1.4 术语定义</span>

| 术语 | 说明 |
|---|---|
| 审批模板 | 预定义的审批规则，包含表单字段和审批流程节点 |
| 审批节点 | 审批流程中的一个步骤，定义了由谁来审批 |
| 审批流转 | 申请从提交到最终通过/驳回的完整路径 |
| 直属领导 | 组织架构中员工的直接上级 |
| 部门总监 | 部门负责人 |
| 会签 (COUNTER_SIGN) | 节点上所有审批人都同意才进入下一步 |
| 或签 (OR_SIGN) | 任一审批人同意即进入下一步 |
| 条件分支 | 根据请假类型/天数等条件动态跳过或触发审批节点 |
| 超时自动升级 | 审批超时后自动执行指定动作（转派/通过/驳回） |

## 2. システム全体概要
> <span style="color: #888888;">## 2. 系统总体描述</span>

### 2.1 製品視点
> <span style="color: #888888;">### 2.1 产品视角</span>

SmartOAは、B/Sアーキテクチャに基づくWebアプリケーションシステムであり、フロントエンドとバックエンドを分離したアーキテクチャを採用している。フロントエンドはVue 3 + Element PlusでSPAを構築し、バックエンドはSpring Boot + MyBatis-PlusでRESTful APIを提供し、データはMySQL 8に格納される。
> <span style="color: #888888;">SmartOA 是一个基于 B/S 架构的 Web 应用系统，采用前后端分离架构。前端使用 Vue 3 + Element Plus 构建 SPA，后端使用 Spring Boot + MyBatis-Plus 提供 RESTful API，数据存储在 MySQL 8 中。</span>

### 2.2 ユーザー権限
> <span style="color: #888888;">### 2.2 用户角色</span>

| 角色 | 职责 | 权限级别 |
|---|---|---|
| EMPLOYEE（普通员工） | 提交申请，查看个人申请历史，撤回自己的申请 | 基础 |
| MANAGER（管理员/审批人） | 审批待办、管理模板、导出数据、查看报表 | 高级 |

### 2.3 実行環境
> <span style="color: #888888;">### 2.3 运行环境</span>

- サーバー側：JDK 21 + Spring Boot 3.5.14
- データベース：MySQL 8.0+
- クライアント：モダンブラウザ（Chrome / Firefox / Edge）
- ネットワーク：HTTP/HTTPS
> <span style="color: #888888;">
> - 服务端：JDK 21 + Spring Boot 3.5.14
> - 数据库：MySQL 8.0+
> - 客户端：现代浏览器（Chrome / Firefox / Edge）
> - 网络：HTTP/HTTPS
> </span>

### 3.1 ユーザー認証モジュール (AUTH)
> <span style="color: #888888;">### 3.1 用户认证模块 (AUTH)</span>

#### 3.1.1 ログイン
> <span style="color: #888888;">#### 3.1.1 登录</span>

| 需求编号 | AUTH-001 |
|---|---|
| 描述 | 用户通过用户名和密码登录系统 |
| 输入 | 用户名（username）、密码（password） |
| 处理 | 查询用户表验证 BCrypt 密码，生成 JWT Token |
| 输出 | `Result<Map>` 含 Token + 用户基本信息（不含密码） |
| 异常 | 用户名或密码错误时返回失败提示 |
| Token 有效期 | 24 小时（86400000ms） |

#### 3.1.2 認証インターセプト
> <span style="color: #888888;">#### 3.1.2 认证拦截</span>

| 需求编号 | AUTH-002 |
|---|---|
| 描述 | 除登录接口外，所有 /api/* 接口需 JWT 认证 |
| 处理 | JwtFilter 拦截请求，验证 Authorization 头中的 Bearer Token |
| 异常 | 无 Token / Token 无效 / Token 过期 / 用户不存在 → 401 |

#### 3.1.3 現在のユーザー取得
> <span style="color: #888888;">#### 3.1.3 获取当前用户</span>

| 需求编号 | AUTH-003 |
|---|---|
| 描述 | 客户端可根据 Token 获取当前登录用户信息 |
| 输出 | 用户 ID、用户名、姓名、角色、部门、组织层级 ID |

#### 3.1.4 ユーザー一覧
> <span style="color: #888888;">#### 3.1.4 用户列表</span>

| 需求编号 | AUTH-004 |
|---|---|
| 描述 | 前端获取所有用户列表（用于选择审批人） |
| 输出 | User[] 数组，password 字段被 @JsonIgnore 排除 |

### 3.3 休暇申請モジュール (LEV)
> <span style="color: #888888;">### 3.3 请假申请模块 (LEV)</span>

#### 3.3.1 申請の提出
> <span style="color: #888888;">#### 3.3.1 提交申请</span>

| 需求编号 | LEV-001 |
|---|---|
| 描述 | 员工提交请假申请，系统自动启动审批流程 |
| 输入 | templateId、leaveType、startDate、endDate、reason |
| 处理 | 1. 验证用户存在 2. 创建 LeaveRequest 3. 推进到第一个满足条件的审批节点 4. 根据节点模式设置 currentApproverId 或创建 approval_task |
| 前置条件 | 申请人已分配直属领导 |
| 状态 | PENDING |

#### 3.3.2 承認操作
> <span style="color: #888888;">#### 3.3.2 审批操作</span>

| 需求编号 | LEV-002 |
|---|---|
| 描述 | 审批人对申请进行通过或驳回操作 |
| 输入 | requestId、action（APPROVE/REJECT）、comment |
| 校验 | 1. 申请存在 2. 状态为 PENDING 3. 操作人匹配（SINGLE: currentApproverId；并行: approval_task 中有 PENDING 任务） |
| 通过处理 | 单人→推进；或签→跳过其余+推进；会签→如全部完成则推进 |
| 驳回处理 | 记录审批 → 标记 REJECTED → 跳过并行任务 → 流程终止 |

#### 3.3.3 申請の取り下げ
> <span style="color: #888888;">#### 3.3.3 撤回申请</span>

| 需求编号 | LEV-003 |
|---|---|
| 描述 | 申请人在审批完成前撤回申请 |
| 权限 | 仅申请人 |
| 前置条件 | 状态为 PENDING |
| 处理 | 状态 → WITHDRAWN，跳过并行任务，currentApproverId/currentNodeId/timeoutTime → null |

#### 3.3.4 承認の転送

### 5.1 パフォーマンス
> <span style="color: #888888;">### 5.1 性能</span>

| 指标 | 要求 |

### 5.2 セキュリティ
> <span style="color: #888888;">### 5.2 安全性</span>

| 要求 | 实现 |
|---|---|
| 认证 | JWT Bearer Token（jjwt 0.13.0） |
| 密码保护 | BCrypt 加密（spring-security-crypto），不返回给前端 |
| 越权防护 | 操作前校验身份（撤回=申请人，审批=当前审批人/并行任务） |
| CORS | 仅允许前端域名跨域 |

### 5.3 ユーザビリティ
> <span style="color: #888888;">### 5.3 可用性</span>

- フォームはリアルタイムバリデーションとエラーヒントを提供する
- 操作には成功／失敗のフィードバックがある（ElMessage）
- ボタンの状態は権限と連動する（権限がない場合は非表示）
- 承認プログレスバーでフローの現在位置を直感的に表示する
- タイムアウト警告バーで期限を通知する
> <span style="color: #888888;">
> - 表单提供实时校验和错误提示
> - 操作有成功/失败反馈（ElMessage）
> - 按钮状态与权限联动（无权限时隐藏）
> - 审批进度条直观展示流程位置
> - 超时警告栏提示截止时间
> </span>

### 5.4 保守性
> <span style="color: #888888;">### 5.4 可维护性</span>

- バックエンド：レイヤードアーキテクチャ（Controller → Service → Mapper）、統一レスポンス `Result<T>`
- フロントエンド：Pinia状態管理 + APIレイヤーの分離
- データベース：マイグレーションスクリプトのバージョン管理（mysql-p0 ~ mysql-p5）
- グローバル例外処理：BusinessException + @RestControllerAdvice
> <span style="color: #888888;">
> - 后端：分层架构（Controller → Service → Mapper），统一响应 `Result<T>`
> - 前端：Pinia 状态管理 + API 层独立
> - 数据库：迁移脚本版本化管理（mysql-p0 ~ mysql-p5）
> - 全局异常处理：BusinessException + @RestControllerAdvice
> </span>
