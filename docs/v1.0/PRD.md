# 製品要件ドキュメント (PRD)

## SmartOA — 簡易 OA 承認フロー管理システム

---

## 1. 製品概要

### 1.1 製品ポジショニング

SmartOA は中小企業向けの軽量 OA 承認フロー管理システムであり、社内の休暇・経費精算・残業などの日常的な承認シーンをオンライン化することを中核課題としています。システムは「テンプレート設定 + 多段階承認 + フローエンジン」を中核アーキテクチャとし、条件分岐、並列承認（会簽/或簽）、タイムアウト自動エスカレーションなどの高度な機能をサポートします。

### 1.2 製品目標

| 目標 | 説明 |
|---|---|
| 承認のオンライン化 | 紙・メール・WeChat など断片化された承認手段を代替 |
| 柔軟な設定 | 管理者が承認テンプレート、フローノード、署名モードを自由にカスタマイズ可能 |
| 全工程の追跡 | すべての承認操作が記録され、履歴の確認が可能 |
| データの可視化 | 承認データの統計グラフにより、管理判断をサポート |
| インテリジェントなフロー | 条件分岐 + タイムアウト自動エスカレーションにより、手動介入を削減 |

### 1.3 対象ユーザー

| 役割 | 説明 |
|---|---|
| 一般社員 (EMPLOYEE) | 申請提出、自分の申請記録の確認、申請取り下げ |
| 承認者 (MANAGER) | 承認待ち申請の承認/却下/転送、処理済み記録の確認 |
| 管理者 (MANAGER) | 承認テンプレートの管理、承認ノードの設定、データエクスポート |

## 2. 機能要件

### 2.1 P0 コア機能（実装済み）

| モジュール | 機能 | 説明 |
|---|---|---|
| ログイン認証 | JWT ログイン/ログアウト | ユーザー名・パスワードログイン、BCrypt 暗号化、Bearer Token 認証 |
| 承認テンプレート | テンプレート CRUD | 承認テンプレートの作成/編集/削除/閲覧 |
| 申請提出 | 休暇申請 | 休暇種類の選択、日付範囲、理由を入力して提出 |
| 承認フロー | 2段階ハードコード承認 | P0 固定フロー：直属上司 → 部門長 |
| 承認待ち/処理済み | 自分の承認ページ | タブ切替で承認待ち/処理済み/自分の申請を表示 |
| 承認詳細 | 閲覧+操作 | 申請詳細の閲覧、承認/却下操作 |

### 2.2 P1 拡張機能（実装済み）

| モジュール | 機能 | 説明 |
|---|---|---|
| 技術アップグレード | JPA → MyBatis-Plus | 永続層フレームワークの置き換え、より柔軟なクエリ機能 |
| 設定可能エンジン | テンプレートカスタム承認ノード | 各テンプレートに N 段階の承認ノードを自由に設定可能 |
| 承認アクション | 承認/却下/取り下げ/転送 | 4種類の完全な承認操作 |
| 統計レポート | ECharts 可視化 | 平均承認時間の棒グラフ + テンプレート使用量の円グラフ |
| データエクスポート | Excel エクスポート | 管理者が全休暇申請を .xlsx にエクスポート可能 |
| フロントエンド強化 | 動的ステップバー/タイムライン | el-steps が動的に承認ノードを読み取り、Timeline が完全なフロー記録を表示 |

### 2.3 P2 高度機能（実装済み）

| モジュール | 機能 | 説明 |
|---|---|---|
| フローエディタ | ビジュアルノード設定 | ドラッグソート、動的なノード追加/削除、署名モード選択 |
| 条件分岐 | SpEL 条件式 | `leaveType`/`days`/`startDate`/`endDate` に基づいて動的にノードをトリガー |
| 並列承認 | 会簽 (COUNTER_SIGN) | ノード上の全承認者が同意してから次へ進む |
| 並列承認 | 或簽 (OR_SIGN) | いずれかの承認者が同意すれば次へ進む |
| タイムアウトエスカレーション | タイムアウト自動処理 | ESCALATE（転送）/ AUTO_APPROVE（自動承認）/ AUTO_REJECT（自動却下） |
| 滞留修復 | 異常状態の修復 | currentApproverId が null の滞留申請を修復 |

### 2.4 承認者タイプ

| タイプ | 説明 |
|---|---|
| DIRECT_LEADER | 申請者の直属上司 |
| DEPARTMENT_HEAD | 申請者の所属部門の部門長 |
| SPECIFIC_USER | 特定ユーザーを指定（単人/複数人） |

### 2.5 署名モード

| モード | 進行条件 | 説明 |
|---|---|---|
| SINGLE | 単人承認 | デフォルトモード、1人の承認者が決定 |
| COUNTER_SIGN | 全員同意 | 会簽、全員が通過してから進行 |
| OR_SIGN | いずれか同意 | 或簽、いずれか1人が通過すれば進行 |

### 2.6 承認フロー状態

```
申請提出 → PENDING（承認中）
  ├─ 承認（SINGLE）→ 次のノードへ → ... → APPROVED（承認済み）
  ├─ 承認（COUNTER_SIGN）→ 他者の待機 → ... → APPROVED
  ├─ 承認（OR_SIGN）→ 他者をスキップ → 次のノードへ → ... → APPROVED
  ├─ 却下 → REJECTED（却下済み）+ 並列タスクをスキップ
  ├─ 取り下げ → WITHDRAWN（取り下げ済み）+ 並列タスクをスキップ
  └─ タイムアウト → ESCALATE/AUTO_APPROVE/AUTO_REJECT
```

## 5. 非機能要件

| 項目 | 要件 |
|---|---|
| パフォーマンス | ページ応答 < 2s、API 応答 < 500ms |
| セキュリティ | JWT 認証、BCrypt パスワード暗号化、パスワードはフロントエンドに返さない、CORS 制限 |
| 互換性 | Chrome/Firefox/Edge 最新版 |
| ユーザビリティ | Element Plus UI 規範、フォームバリデーション、タイムアウト警告バー |
| データ | MySQL 8 ストレージ、utf8mb4 文字セット、8 テーブル |
| 定期タスク | タイムアウトチェックを 5 分ごとに実行 |
